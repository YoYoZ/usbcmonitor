# Режим настройки ↔ рабочий режим

**Wi-Fi и SSH работают в обоих режимах** (решение владельца, 2026-09-29: сеть привязана к
домашней, выключать её незачем). Режимы отличаются только тем, пишется ли что-то на SD-карту.

| | Режим настройки | Рабочий режим |
|---|---|---|
| Корень `/` | обычный, запись на карту | **только для чтения** (overlayroot: записи идут в RAM и пропадают при перезагрузке) |
| `/boot/firmware` | только для чтения (скрипты перемонтируют на запись сами) | то же |
| initramfs | выключен (`auto_initramfs=0`), быстрее на пару секунд | включён (нужен overlayroot), fsck выключен (`fastboot`) |
| Выдёргивание питания | может оставить пустой только что записанный файл — после правок `sync` | безопасно |
| Журнал | в RAM, до 16 МБ (`/etc/systemd/journald.conf.d/usbcmonitor.conf`) | то же |

## Переключение

```bash
sudo usbc-mode-production.sh && sudo reboot   # включить только-чтение
sudo usbc-mode-setup.sh && sudo reboot        # выключить, чтобы что-то поменять
```

Проверить текущий режим: `grep -o overlayroot=tmpfs /proc/cmdline` (есть — рабочий режим)
или `findmnt /` (в рабочем режиме тип `overlay`).

**Важно:** в рабочем режиме любые изменения на плате (правки скриптов, `apt install`,
новый профиль Wi-Fi) исчезнут после перезагрузки. Сначала `usbc-mode-setup.sh`, перезагрузка,
правки, `sync`, потом `usbc-mode-production.sh`, перезагрузка.

## Аварийный доступ

SSH по Wi-Fi работает всегда. Если сеть недоступна: serial-консоль (`console=serial0,115200`
в `cmdline.txt`, USB-UART 3.3V на GPIO14/15/GND) или SD-карта в ПК — в разделе `bootfs`
убрать `overlayroot=tmpfs ` из начала `cmdline.txt`.
